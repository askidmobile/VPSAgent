# План: VPSAgent — агентская CLI-система на Rust

**Дата:** 2026-08-03
**Статус:** Реализовано (с фазой стабилизации после код-ревью)
**Приоритет:** P1
**Спецификация:** [docs/specs/2026-08-03-vpsagent.md](../specs/2026-08-03-vpsagent.md)

## Цель

Построить агентскую CLI-систему: headless-демон (держит агентов и сессии) + thin
TUI-клиент (Ratatui) с attach/detach по SSH, порт возможностей Codex CLI / Claude
Code плюс киллер-фичи: самогенерация скиллов, фабрика субагентов, A/B-раннер,
роутер моделей с OmniRoute, deck-UI, мультипоток.

## Текущее состояние

Зелёное поле. Существуют только `BRIEF.md` и `docs/specs/2026-08-03-vpsagent.md`.
Кодовой базы, Cargo-проекта, git-репозитория нет. Все файлы создаются с нуля.

**Поток данных (основной цикл):**
1. Клиент → `message.send` (JSON-RPC) → daemon
2. SessionManager находит/создаёт tokio-таску агента → AgentLoop
3. AgentLoop → Router выбирает endpoint → Provider стримит (SSE)
4. Каждый чанк/tool call → событие `Event` → storage (append) + broadcast подписанным клиентам
5. Tool calls → ToolExecutor (permissions check) → результат → следующий виток цикла

| Метод | Вход | Выход | Описание |
|-------|------|-------|----------|

| `daemon.restart` | — | ack | graceful restart (exec нового бинаря) |
| `session.create` | `NewSession{cwd, model?}` | `Session` | новая сессия + главный агент |
| `session.list` | — | `Vec<Session>` | все сессии |
| `session.attach` | `{session_id}` | snapshot + subscription | полная история + push-подписка на события |
| `session.detach` | `{session_id}` | ack | отписка, агенты продолжают работать |
| `message.send` | `{session_id, text, target?}` | ack | сообщение (target — явный адресат, иначе классификатор) |
| `agent.list` | `{session_id}` | `Vec<AgentInfo>` | карточки для deck-обзора |
| `agent.interrupt` | `{agent_id}` | ack | мягкая остановка агента |
| `skill.list` / `skill.invoke` | `{name, args}` | `Vec<Skill>` / ack | скиллы |
| `ab.start` / `ab.verdict` | `{task, models}` / `{run_id, winner}` | `AbRun` / ack | A/B-раннер |
| `router.rules.get/set` | `Vec<RouteRule>` | `Vec<RouteRule>` | правила роутера |

#### Механики (псевдокод):

```pseudo
fn ensure_daemon() -> Result<DaemonHandle>:
    lock = try_flock(socket_path + ".lock")
    if lock.held_by_other: return Connect(existing_socket)
    daemonize()                       // fork, setsid, detach от tty → переживает SIGHUP
    storage::migrate(db_path)
    sessions = storage::load_active_sessions()
    for s in sessions: session_manager.resume(s)   // агенты в статусе Working → прерваны, ждут attach
    rpc_server.serve(unix_socket, mode=0o600)

fn broadcast.subscribe(session_id, last_seq) -> Stream<Event>:
    yield storage::events_since(session_id, last_seq)   // replay пропущенного
    yield live_channel(session_id)                      // дальше push
```

#### Harness-цикл (псевдокод, FR-027):

```pseudo
async fn run_agent(agent: AgentHandle, inbox: Receiver<UserMessage>):
    loop:
        // 1. Сборка контекста (context.rs)
        let request = assemble(system_prompt, memory_tree(cwd), skills_index,
                               env_info(cwd, git), history, tools=agent.allowed_tools)
        // 2. Роутинг и стрим с ретраями
        let model = router.resolve(agent.task_profile)
        let stream = retry_with_backoff(max=5, on=[429,5xx,Overloaded]):
            provider.stream(request, model)          // экспонента + джиттер, событие RetryWait клиенту
        // 3. Чтение стрима
        while let Some(chunk) = stream.next().await:
            if cancel_token.is_cancelled():            // Esc / agent.interrupt — мягкая остановка,
                save_partial(); break                  //   сессия и история сохраняются
            match chunk:
                TextDelta(t) => emit(TextDelta)
                ToolCalls(calls) =>                    // параллельный блок вызовов
                    results = join_all(calls.map(|tc| async {
                        let decision = permissions.pipeline(tc)   // hooks(PreToolUse) → allow/deny
                        if decision == Ask:                       //   → режим → запрос клиенту
                            wait_client_decision(tc).await        //   (PermissionDialog / ask_user)
                        let out = tool_executor.run(tc).await
                        truncate::apply(out)                      // лимит ~30k chars, полный вывод → файл
                    }))
                    history.push(results); emit(ToolCallEnd)
                Done => break
        // 4. Межвитковые проверки
        drain(inbox) -> history                        // steering/мультипоток без прерывания
        if context_near_limit(): compact::summarize()  // FR-070
        if turns > MAX_TURNS: escalate_to_user(); break
        if !stream.had_tool_calls: break
    agent.set_status(Done)

fn permissions.pipeline(tc) -> Decision:               // порядок строгий:
    hooks.pre_tool(tc)?  -> deny/modify                // 1. пользовательские хуки (FR-060)
    rules.match(tc)      -> allow/deny                 // 2. allow/deny-листы (FR-012)
    mode                 -> Allow(acceptEdits/bypass) | Ask(default) | Deny(plan для не-readonly)
```

#### Инструменты и события

Каждый инструмент — реализация `trait Tool { name, schema() -> JsonSchema, run(args, ctx) -> ToolResult }`.
Схемы генерируются в tool-use формат провайдера. Субагент получает `allowed_tools = parent.tools ∩ definition.tools`
(сужение, FR-015); `ask_user`, `task_list/stop`, `create_skill`, `ab_run` — только главному (см. реестр в спеке).

```pseudo
fn spawn_subagent(parent, def: AgentDefinition, task: String) -> AgentHandle:
    assert depth < MAX_DEPTH (default 3)
    child_ctx = isolated_context(def.prompt, task)      // без истории родителя
    child_tools = parent.tools ∩ def.tools              // сужение прав (FR-015)
    handle = tokio::spawn(run_agent(child, inbox_child))
    subagent_manager.register(child, handle)            // JoinSet: task_list/output/stop
    emit(AgentSpawned(child))
```

### Мультипоток (фаза 7, `crates/runtime/src/classifier.rs`)

```pseudo
fn classify(msg, ctx: SessionContext) -> Route:
    // 1. эвристики (D2)
    if msg starts "/tell <name>":  return Route::ToAgent(name)
    if msg starts "/new":          return Route::SpawnNew
    if msg contains "@<name>":     return Route::ToAgent(name)
    if ctx.focused_agent.kind == Sub && msg looks_like steering: return Route::ToAgent(focused)
    // 2. LLM-fallback: маленькая модель из роутера, JSON-ответ
    llm_verdict = cheap_model.classify(msg, agents_summary)
    if llm_verdict.confidence < 0.7: return Route::AskUser(candidates)
    return llm_verdict.route
```

### A/B-раннер (фаза 5, `crates/runtime/src/ab.rs`)

```pseudo
fn ab_start(task, models[]) -> AbRun:
    worktrees = [git_worktree_copy(cwd) for _ in models]   // изоляция правок
    agents = [spawn_subagent(model=m, cwd=worktrees[i]) for (i,m) in models]
    run.track(agents)
fn ab_finish(run):
    metrics = collect(duration, tokens, cost, tests_passed(worktree))
    storage.ab_results.insert(metrics); event AbFinished → клиент (ab_view)
fn ab_verdict(run_id, winner):
    storage.verdict; router.stats.learn(winner, task_profile)
```

### Уроки

1. **Код-ревью после реализации — обязательный шаг.** Скелет прошёл 8 фаз и
   казался «готовым», но независимый ревью (4 параллельных ревьюера, 79 находок)
   выявил критические дефекты: обход прав, path traversal, SSRF, паника на
   кириллице, сломанный tool-calling у всех провайдеров, сломанная multi-turn
   история, мёртвый TUI, 6 заглушек-фич. **Рекомендация: ревью встроить в
   pipeline после каждой крупной фазы, не в конце.**

2. **История сообщений — архитектурное решение с далеко идущими последствиями.**
   Хранение `Vec<ContentBlock>` без ролей (для «простоты») сломало multi-turn
   во всех провайдерах. Правильная модель (`Vec<Message>` с ролями) должна быть
   заложена в Фазе 1, а не исправлена в стабилизации. **Рекомендация: роли —
   часть доменной модели с первого дня.**

3. **Заглушки с ложными результатами опаснее честного «не реализовано».**
   todo, ask_user, A/B, critic, fork возвращали фиктивные ответы — модель и
   роутер принимали решения на ложных данных. **Рекомендация: заглушка должна
   либо падать (unimplemented), либо честно помечаться «не работает», но не
   возвращать валидный-на-вид результат.**

4. **Субагенты-фиксеры хрупки к лимитам провайдера.** 5 параллельных агентов
   упали на лимитах одновременно (общий пул). Изменения частично сохранились,
   но интеграция потребовала ручной доработки. **Рекомендация: для массовых
   фиксов — меньше параллелизма (2-3 агента), чёткие непересекающиеся области,
   обязательный прогон сборки после каждого.**

5. **Эвристические решения вместо LLM требуют честной маркировки.**
   Компактификация реализована эвристикой (без суммаризации моделью), роутер
   без ML, classifier без LLM-fallback. Это корректно для скелета, но должно
