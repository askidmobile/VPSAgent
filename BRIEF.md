# Бриф проекта: VPSAgent

> Составлен по итогам discovery-опроса (скилл `discovery-interview`, 2026-08-02).
> Референсы: Codex CLI, Claude Code, Hermes (самогенерация скиллов), dot-agent-deck (обзор агентов).

## 1. Суть проекта

Собственная агентская CLI-система на **Rust** (не JS/Node/TS), воспроизводящая
возможности современных агентских систем (Codex CLI, Claude Code) с акцентом на:

- **Экономию ресурсов и памяти** — один статический бинарь, никакого рантайма Node.
- **Серверный сценарий** — агент живёт на VPS, пользователь подключается по SSH,
  отключается — агенты продолжают работать (модель tmux/Zellij).
- **Киллер-фичи**: самогенерация скиллов (как Hermes), создание и тестирование
  субагентов, параллельный запуск субагентов для A/B-исследований, роутинг моделей
  (интеграция с OmniRoute), живой обзор работающих агентов (как dot-agent-deck),
  мультипоток — сообщения агентам без прерывания основного процесса.

## 2. Ключевые архитектурные решения (утверждено в опросе)

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Язык | **Rust + tokio** (Ratatui для TUI) |
| 2 | Персистентность | **Клиент-сервер: headless-демон + thin TUI-клиент**, attach/detach |
| 3 | Провайдеры LLM | **Свой роутер** + OpenAI-compatible + Anthropic API; OmniRoute — как один из endpoint'ов |
| 4 | Скиллы | **Совместимые SKILL.md** (экосистема Claude Code) + расширения (executable-скрипты) |
| 5 | Субагенты | **Tokio-таски внутри демона** с изолированным контекстом и своим набором инструментов |
| 6 | Мультипоток | **Классификатор-роутер сообщений**: новый агент / вмешательство / уточнение / параллельный диалог |
| 7 | UI агентов | **Deck-обзор** (карточки всех агентов) **+ фокус-режим** (полный стрим одного) |
| 8 | A/B-тесты | **Встроенный /ab-раннер**: N агентов × разные модели, side-by-side, метрики, вердикт → статистика роутера |
| 9 | Хранение | **SQLite в демоне** (сессии, события, статистика роутера, A/B-результаты) |
| 10 | MCP | **MCP-клиент (stdio + HTTP) + сам CLI — MCP-сервер** |
| 11 | Протокол клиент↔демон | **JSON-RPC поверх Unix-сокета**, удалённо — SSH-туннель; server-push стриминг |
| 12 | MVP | **Скелет end-to-end, фичи фазами** |

### Решения по умолчанию (не заданы в опросе, можно изменить)

- **Права доступа**: режимы как в Claude Code/ZCode (default / acceptEdits / plan /
  bypassPermissions) + allow/deny-листы; субагенты наследуют права родителя с сужением.
- **Определение субагентов**: markdown + frontmatter (совместимость с `~/.claude/agents`).
- **Название**: рабочее — `vpsagent`.
- **Лицензия**: приватная разработка → MIT/Apache-2.0 при релизе; статический бинарь
  (musl) для Linux/macOS.

## 3. Возможности (полный порт референсов + новое)

### Портируется из Codex CLI / Claude Code
- Интерактивный TUI-диалог со стримингом, режимы разрешений, slash-команды.
- Инструменты: файловые операции, shell, поиск (grep/glob), web-fetch.
- Скиллы (SKILL.md), субагенты (markdown + frontmatter), hooks, MCP.
- Сессии с resume/rewind, история, контекстное окно с компактификацией.
- План-режим, фоновые задачи, очередь сообщений.

### Новое (дифференциация)
- **Daemon-first**: attach/detach по SSH, несколько клиентов на одну сессию.
- **Самогенерация скиллов**: агент пишет, тестирует и регистрирует новые SKILL.md.
- **Фабрика субагентов**: создание агента → прогон на тестовых задачах → вердикт.
- **A/B-раннер**: `/ab "задача" --models a,b,c` — параллельные прогоны, метрики
  (время, токены, прохождение тестов), результат подпитывает роутер моделей.
- **Роутер моделей**: правила «задача → модель», обучается на A/B-статистике,
  OmniRoute как источник endpoint'ов.
- **Deck-UI**: панель всех агентов (статус, действие, токены) + фокус-режим.
- **Мультипоток**: сообщение в любой момент; классификатор направляет его главному
  агенту, конкретному субагенту или спавнит нового.

## 5. Фазы реализации (стратегия «скелет end-to-end»)

1. **Фаза 1 — Скелет**: демон + TUI + один агент (fs, shell) + OpenAI-compatible
   провайдер + attach/detach по SSH + SQLite-сессии.
2. **Фаза 2 — Субагенты**: tokio-таски, определения из markdown, deck-обзор + фокус.
3. **Фаза 3 — Скиллы**: загрузка SKILL.md, самогенерация и регистрация скиллов.
4. **Фаза 4 — Роутер моделей**: правила, OmniRoute-endpoint'ы, статистика.
5. **Фаза 5 — A/B-раннер**: параллельные прогоны, метрики, side-by-side в TUI.
6. **Фаза 6 — MCP**: клиент (stdio/HTTP) + серверный режим.
7. **Фаза 7 — Мультипоток**: классификатор-роутер сообщений, steering субагентов.
8. **Фаза 8 — Полировка**: hooks, plan-режим, компактификация, rewind, релиз.

## 6. Основные риски

- **Масштаб в одиночку** — смягчается фазовой стратегией: работающий скелет с 1-й недели.
- **Совместимость SKILL.md** — формат неформализован; нужен толерантный парсер.
- **Классификатор мультипотока** — риск неверной маршрутизации; явные команды
  (`/tell`, `/new`, `/steer`) как fallback (рекомендую добавить сразу).
- **Ratatui-сложность** — deck-UI со сплитами и фокусом потребует аккуратной
  state-архитектуры (рекомендуется Component- паттерн как в ratatui-templates).
